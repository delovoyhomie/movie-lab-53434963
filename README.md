Разработанная система должна удовлетворять следующим требованиям:

—

Основное назначение информационной системы - управление объектами, созданными на основе заданного в варианте класса.

—

Необходимо, чтобы с помощью системы можно было выполнить следующие операции с объектами: создание нового объекта, получение информации об объекте по ИД, обновление объекта (модификация его атрибутов), удаление объекта. Операции должны осуществляться в отдельных окнах (интерфейсах) приложения. При получении информации об объекте класса должна также выводиться информация о связанных с ним объектах.

—

При создании объекта класса необходимо дать пользователю возможность связать новый объект с объектами вспомогательных классов, которые могут быть связаны с созданным объектом и уже есть в системе.

—

Выполнение операций по управлению объектами должно осуществляться на серверной части (не на клиенте), изменения должны синхронизироваться с базой данных.

—

На главном экране системы должен выводиться список текущих объетов в виде таблицы (каждый атрибут объекта - отдельная колонка в таблице). При отображении таблицы должна использоваться пагинация (если все объекты не помещаются на одном экране).

Нужно обеспечить возможность фильтровать/сортировать строки таблицы, которые показывают объекты (по значениям любой из строковых колонок). Фильтрация элементов должна производиться по неполному совпадению.

—

Переход к обновлению (модификации) объекта должен быть возможен из таблицы с общим списком объектов и из области с визуализацией объекта (при ее реализации).

При добавлении/удалении/изменении объекта, он должен автоматически появиться/исчезнуть/измениться в интерфейсах у других пользователей, авторизованных в системе.

—

Если при удалении объекта с ним связан другой объект, связанные объекты должны удаляться.

—

Пользователи должны иметь возможность просмотра всех объектов. Для модификации объекта должно открываться отдельное диалоговое окно. При вводе некорректных значений в поля объекта должны появляться информативные сообщения о соответствующих ошибках.

В системе должен быть реализован отдельный пользовательский интерфейс для выполнения специальных операций над объектами:

—

Удалить один (любой) объект, значение поля tagline которого эквивалентно заданному.

Вернуть массив объектов, значение поля tagline которых содержит заданную подстроку.

Вернуть массив объектов, значение поля genre которых меньше заданного.

Получить список сценаристов, ни один фильм которых не получил ни одного "Оскара".

Представленные операции должны быть реализованы в качестве функций БД, которые необходимо вызывать из уровня бизнес-логики приложения.

## Запуск на Helios

Приложение установлено в `~/movie-lab` на `helios.cs.ifmo.ru`, HTTP-порт — `40946`.
PostgreSQL: `pg:5432`, база `studs`, схема `s409946`.
Таблицы и SQL-функции этой работы имеют префикс `ml53434963_`: в схеме уже есть таблицы других работ.
Пароль БД читается на сервере из `~/.pgpass`.

Открыть SSH-туннель на своём компьютере и оставить терминал открытым:

```sh
ssh -p 2222 -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 18081:127.0.0.1:40946 s409946@helios.cs.ifmo.ru
```

Адрес в браузере: http://127.0.0.1:18081/movie-lab/.
Браузер обращается через SSH-туннель к приложению на Helios. Docker для этого не нужен.
Если туннель уже открыт, второй раз эту команду выполнять не нужно.

Если приложение остановлено, подключиться к Helios и запустить его
(в другом терминале, отдельно от туннеля):

```sh
ssh -p 2222 s409946@helios.cs.ifmo.ru
~/movie-lab/start.sh
```

Посмотреть логи на Helios:

```sh
tail -f ~/movie-lab/console.log
```

Остановить приложение на Helios, когда это потребуется:

```sh
~/movie-lab/stop.sh
```

`start.sh` запускает приложение в фоне. Закрытие SSH не останавливает его.
После перезагрузки Helios нужно снова выполнить `start.sh`.

### Запросы с Mac, без входа в терминал Helios

На Mac используется порт `18081` — он перенаправляется туннелем на порт `40946` на Helios.
Если туннеля ещё нет, открыть его командой выше. После ввода SSH-пароля терминал
будет ждать без вывода — это нормально. Оставить его открытым, а `curl` выполнять
в другом окне терминала на Mac.

Получить первые пять фильмов:

```sh
curl -i 'http://127.0.0.1:18081/movie-lab/api/movies?page=0&size=5'
```

Сортировать фильмы по бюджету от большего к меньшему:

```sh
curl -i 'http://127.0.0.1:18081/movie-lab/api/movies?sort=budget&desc=true&size=5'
```

Найти фильмы с длительностью 137 минут:

```sh
curl -i 'http://127.0.0.1:18081/movie-lab/api/movies?column=length&q=137'
```

Добавить фильм (ID координат и режиссёра взять из `/api/references`):

```sh
curl -i -H 'Content-Type: application/json' -d '{"name":"Новый фильм","coordinatesId":1,"directorId":7,"budget":100,"totalBoxOffice":200,"mpaaRating":"PG","length":100,"genre":"ACTION"}' http://127.0.0.1:18081/movie-lab/api/movies
```

### Запросы, когда уже подключён по SSH к Helios

Если приглашение терминала выглядит как `[s409946@helios ~]$`, команды выполняются
на сервере. Здесь используется порт `40946`, туннель для этих запросов не нужен.
Если ещё не подключён к серверу:

```sh
ssh -p 2222 s409946@helios.cs.ifmo.ru
```

В терминале Helios запросить список:

```sh
curl -i 'http://127.0.0.1:40946/movie-lab/api/movies?page=0&size=5'
```

Пример фильтра и сортировки: фильмы жанра COMEDY, по бюджету от меньшего к большему.

```sh
curl -i 'http://127.0.0.1:40946/movie-lab/api/movies?column=genre&q=COMEDY&sort=budget&desc=false'
```

`-i` показывает HTTP-статус и заголовки ответа.

`Failed to connect` — проверить порт, туннель и запуск приложения.
На Mac обращаться к `40946` не нужно: это порт приложения внутри Helios.

- Бюджет и сборы — доллары США, длительность — минуты. Поле сборов имеет тип `float`, поэтому возможны округления больших сумм.
- Дата добавления создаётся сервером и не означает дату выхода фильма.
- Координаты — условные значения для модели задания, не география съёмок.
- Указан один из авторов сценария: поле не позволяет хранить нескольких. Жанр выбран из четырёх значений варианта; для смешанных жанров указан один подходящий.
- Имена людей реальны; обязательные цвета глаз/волос (`WHITE`) и рост (180) — условные значения. Допустимые цвета только `RED`, `YELLOW`, `WHITE` не позволяют описать реальные внешние данные. Гражданство и местоположение не заполнены.
- Для «Волшебника страны Оз» указан рейтинг `G` из переиздания 1970 года, приведённый в источнике.

Скрипт также заменяет старые неизменённые записи «Учебный фильм N», сохраняя их ID
и даты добавления. Существующие реальные фильмы и изменённые пользователем записи не перезаписываются.

Поиск по текстовым полям работает по части строки без учёта регистра,
по числам и дате — по точному значению. Для координат можно выбрать ID, X или Y.
Фильтр и сортировка применяются кнопкой «Применить» ко всему списку до разбиения на страницы.
Пустое поле поиска показывает все фильмы. Пустые значения при сортировке идут в конце.
